# moshimo-video

このリポジトリで検証ショート動画を1本作る手順。1本目（`scenes/jihanki.*`）が手本なので、迷ったらそれを読む。構成と確認コマンドは `CLAUDE.md`、これまでの方針は `DECISIONS.md` にある。

順番に意味がある。数字が固まる前に映像を作ると、出典が取れなかった場面を丸ごと作り直すことになる（1本目の試作がそうだった）。企画 → 数字 → 映像 → 音 の順を守る。

## 1. 企画を決める

題材が決まっていなければ、案を5つ出して選んでもらう。伸びやすいのは「身近なもの × ありえない規模」。案ごとに、見どころと 3D の作りやすさを一言添える。

同じ型のくり返しにしない（`DECISIONS.md`「量産しない」）。前の動画と検証の切り口が同じなら、別の切り口を足す。

## 2. 数字を調べる

台本より先に、使えそうな数字の出典を集める。

- 一次情報（公式サイト、業界団体、メーカーの仕様）を優先する。取れなければ、出典を明記した報道まで。
- 出典が取れなかった数字は使わない。その場面は台本から外し、外したことを報告する。記憶にある数字で埋めない。
- 「全国の〇〇」のような数は、何を含む数かで倍ほど変わる。大きさや重さと掛け合わせるなら、対象がそろう範囲に絞る（1本目は全自販機388万台ではなく飲料自販機195万台にした）。

数字と計算は `scenes/<名前>.facts.js` に置く。元の値を `FACTS`、そこからの計算を `derive()` に書き、字幕に出す丸めた数字と合うことを `test/<名前>.facts.test.js` で確かめる。字幕の数字を手で打つと、あとで元の値を直したときにずれるため。

## 3. 台本を書く

`scenes/<名前>.md` に、台本（秒・映像・字幕の表）、数字と出典の表、計算、前提と割り切りを書く。形式は `scenes/jihanki.md` に合わせる。

- 長さは30〜45秒が目安。検証は2〜3個で、最後に意外な結論が来るように並べる。
- 最初の2秒で「もしも〜だったら？」を言い切る。
- 計算の前提（何台として、1つをどの大きさとして）は、小さい注記の字幕で画面にも出す。

台本ができたら、作り込む前にユーザーに見せて確認を取る。ここが一番安く直せる。

## 4. 映像を作る

`scenes/<名前>.js` に `duration` と `build(stage)` を書く。共通の道具は `src/engine.js`（字幕 `createCaptions`、3D に貼りつくラベル `createTags`）と `src/util.js`。

- 場面ごとに `THREE.Group` を分け、時刻で表示を切り替える。
- 場面の切り替わり、物が着く瞬間、字幕が出る時刻は `scenes/<名前>.timing.js` に置き、音楽の拍（120BPM なら0.5秒きざみ）に合わせる。あとから音を拍に合わせようとすると映像の書き出し直しになるので、映像を作る前に決める。
- すべての動きを時刻 `t` の関数にする。コマ書き出しは実時間で進まないので、`Math.random()` や CSS アニメーションを使うと書き出すたびに絵が変わる。乱数は `rng(seed)`、物の落下は式で書く。
- 絵柄はローポリ・トゥーン調。模型は箱・円柱・円錐の組み合わせで足りる。
- 桁が違うものを同じ画面に入れるときは、対数のものさしにしてよい。その場合も画面に出す数値は実際の値にし、台本の「前提と割り切り」に書く。
- 大きさを比べる2つは同じ奥行きに置く。手前に置くと大きく見えて、比較が嘘になる。

### 字幕とラベルの置き場所

縦長 1080×1920。ショートの UI に隠れないよう、字幕は上 200px 前後と 1300〜1650px に置く。字幕は改行しない設定なので、1行は全角11文字 × 文字サイズが 1000px に収まるようにする。3D ラベルは字幕の帯に入らない位置に置く。

### 静止画で確かめる

```bash
node render.cjs <名前> --scale 0.5 --stills 1,5,9
```

各場面から1〜2コマずつ出し、ffmpeg の `hstack` で1枚に並べて見る。字幕の折り返し、字幕とラベルの重なり、被写体が画面から切れていないかを確かめる。直したら同じコマを出し直す。

## 5. 音を付ける

**書く前に `references/sound.md` を読む。** 1本目は音を一度作り直している。メロディを乱数で選ぶ、拍とずれた時刻で鳴らす、1種類の音だけで効果音にする、といった作り方は「鳴っているだけ」になる。

`scenes/<名前>.audio.js` に `buildAudio()` を書く。楽器・ドラム・フィルター・残響は `src/synth.js` にある。外部の音素材は使わない。

- 場面の時刻は `timing.js` から読む（映像と同じ値）。
- BGM はコード進行とメロディを書き、場面ごとに楽器の厚みを変える。オチの前は止める。
- 効果音は重ねて作り、切り替えの手前から溜めて、切り替えの瞬間に当てる。

音は耳で確かめられない。`node tools/audio-report.js <名前>` で帯域のバランス、系統ごとの音量、時刻ごとの立ち上がりを見る。報告には「耳では未確認」と書き、ユーザーに聞いてもらって感想で直す。

音だけ直したときは、数秒で済む付け直しを使う。

```bash
node render.cjs <名前> --audio-only
```

## 6. 本番を書き出す

```bash
node render.cjs <名前>
```

10秒ぶんで約2分半かかる。30秒を超えるものはバックグラウンドで実行し、待つあいだに README の「動画の一覧」と `DECISIONS.md`（この動画で決めた前提）を更新する。

終わったら、動画から10コマほど抜いて並べ、もう一度見る。静止画の確認のあとにコードを直していれば、その結果が入っているのはこの動画だけだからである。`npm run check` も通す。

## 7. 渡す

動画ファイルを送り、次を添える。

- 場面の一覧（秒と内容）
- 数字と出典の表、使わなかった数字とその理由
- 確認したことと、未確認のこと（音、スマホでの見え方）
- 投稿文：タイトル（末尾に `#Shorts`）と説明欄（結論の要約、計算の前提、ハッシュタグ）
- 投稿時の注意：視聴者層は「子ども向けではない」を選ぶ

コードはブランチに置いてプルリクエストにする。
