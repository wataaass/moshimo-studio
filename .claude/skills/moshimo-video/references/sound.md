# 音の作り方（BGM と効果音）

1本目で一度作り直した経験から。最初の版は「音が鳴っているだけ」で、音楽にも演出にもなっていなかった。原因と、直すときに効いた考え方をまとめる。手本は `scenes/jihanki.audio.js`。

## 最初に時刻表を作る

**映像を音楽の拍に合わせる（音ハメ）。** 音を映像に合わせるのではなく、テンポを先に決めて、場面の切り替わり・物が着く瞬間・字幕が出る瞬間をすべて拍の上に置く。120BPM なら0.5秒きざみ。

時刻は `scenes/<名前>.timing.js` に置き、映像（`<名前>.js`）と音（`<名前>.audio.js`）の両方から読む。映像にしか出てこない動き（箱がいつ着地するか、など）も、計算を timing.js に置けば、音を同じ瞬間に鳴らせる。拍の上にあることはテストで確かめる。

## BGM

- **メロディは書く。乱数で選ばない。** 乱数の音列は、音階の中にあっても音楽に聞こえない。8分音符ごとの音を小節単位で書き、和音の音を中心に組む。
- **定番のコード進行を使う。** 明るくて耳になじむのは王道進行（F → G → Em → Am）。終わりは F → G → C で解決させる。途中の山場をあえて解決させずに止めると、次の場面への「引き」になる。
- **音色は役割で選ぶ。** メロディはマリンバ（`mallet`）にグロッケンを1オクターブ上で薄く重ねる。伴奏はウクレレ（`pluck`）を裏拍で刻む。矩形波のピコピコ音は安っぽく聞こえやすい。
- **場面ごとに厚みを変える。** 導入は楽器を少なく、盛り上がる場面でドラムと伴奏を足し、雰囲気を変える場面（宇宙など）ではドラムを半分にして残響を増やす。全編同じ厚みだと平板になる。
- **オチの前は止める。** BGM を残響ごと止めると（`duck` の depth 1、target 'all'）、その静けさが前ふりになる。

## ドラム

定番の作り方がある（`src/synth.js` に入っている）。

| 音 | 作り方 |
|---|---|
| キック | 150Hz から 38Hz へ一気に下がるサイン波 + 出だしの「カチッ」 |
| スネア | 胴の音（200Hz 前後）+ 1kHz より上のノイズ |
| クラップ | 短いノイズを3回 + 余韻 |
| ハイハット | 7kHz より上のノイズ。短ければ閉じた音、長ければ開いた音 |

キックは毎拍、クラップは2・4拍、ハイハットは裏拍、が基本。場面が変わる直前にスネアの連打をだんだん強く入れると、切り替わりが気持ちよくなる。

## 効果音

- **重ねて作る。** 1つの音は「出だしの鋭い音」「本体」「余韻」に分けて作り、`layer` で重ねる。衝撃なら、低いサイン波（重さ）+ こもったノイズ（質感）+ シンバル（余韻）。
- **溜めて、当てる。** 場面転換は、手前0.4秒から「シュッ」（帯域を下から上へ動かしたノイズ）を鳴らし、切り替えの瞬間に「ドン」を当てる。山場の前は上昇音や連打で溜める。
- **音程で意味を伝える。** 低い音は大きさと重さ。上がっていく音は増える・近づく・うまくいく。下がる音は失敗やがっかり。数が積み上がる場面は、音階を上がっていくと「増えている」感じが出る。
- **くり返す音は拍にそろえる。** たくさんの物が続けて鳴る場面は、実際の時刻のまま鳴らすと機関銃のようになる。16分音符のマスに丸め、音階をつけると音楽の一部になる。
- **左右に振る。** 画面の右で起きることは右から鳴らす。
- **入れどころ**: 物が現れる・着く・ぶつかる、場面が変わる、字幕が出る（小さく「ポッ」）、数字や結論が出る。笑いどころには定番の音（ひゅ〜んと下がる笛、チーン）が効く。

## まとめ方（ミックス）

- **系統を分ける。** ドラム・BGM・効果音を別々に置く（`put` の第2引数）。効果音が鳴る瞬間に BGM だけを下げられる。
- **BGM を引っこめる。** キックの瞬間は伴奏をわずかに下げる（depth 0.2 前後）と、リズムがはっきりする。大きな効果音の瞬間はもう少し下げる。
- **残響は部屋鳴りにする。** 単純なやまびこ（1回の遅延）は安く聞こえる。`put` の `rev` で送る量を決める。メロディや鐘は多め、キックやベースには送らない。
- **スマホで聞こえる帯域を使う。** スマホのスピーカーは150Hz より下がほぼ鳴らない。低域に音量を使いすぎると、スマホでは小さくスカスカに聞こえる。ベースには2倍・3倍の高さの音を足し、中域（500Hz〜2kHz）が一番大きくなるようにする。
- **高い音は小さめに。** 同じ音量でも、高い音は強く聞こえる。
- **全体の音量は YouTube の基準に合わせる。** −14 LUFS、ピーク −1dB。`render.cjs` が自動でそろえる。

## 耳の代わりに確かめる

この環境では音を聞けない。数字で確かめ、報告には「耳では未確認」と書く。

```bash
node tools/audio-report.js <名前>
```

見るところ：

- **帯域のバランス**: 中域が一番大きく、低域がそれより少し小さいこと。低域が突出していたらキックとベースを下げる。
- **系統ごとの音量**: 残響が全体より 8〜12dB 小さいこと。近すぎると風呂場のようになる。
- **2秒ごとの音量**: 場面の強弱が狙いどおりか。止めた場面が静かになっているか。
- **時刻ごとの立ち上がり**: 音を当てたい時刻で値が大きいこと。

これで分かるのは「大きく外していないこと」までで、曲として心地よいかは分からない。必ずユーザーに聞いてもらい、感想をもらって直す。
